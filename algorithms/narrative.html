CS 499 Milestone Three: Algorithms and Data Structures Enhancement

For this improvement, I decided to use my Treasure Hunt Game from CS 370 as the relic. The project is based on an 8 × 8 maze where a pirate is an intelligent agent that strives to reach the loot. The initial artifact was based on deep Q-learning. The maze class deals with the environment, valid moves, incentives and the win condition. The experience class saves previous states and rewards so the agent can learn from them. I chose this project because it already shows algorithmic problem solving, but also presented a wonderful opportunity for me to exhibit an alternative way of approaching the same problem.

I added A* pathfinding to the project to improve the algorithms and data structures. A* stores a priority queue to pick which cell to investigate next, a collection of cells that have been explored, and dictionaries for the path costs and previous cell for each location. I used Manhattan distance as the heuristic because the pirate can only move up, down, left or right. When the prize is found, the algorithm backtracks the path from the goal to the initial cell . I also added output for number of movements, path cost and states investigated. Using the original maze, the A* implementation, beginning at (0, 0), finds the treasure at (7, 7) in 24 moves and explores 50 states. This gives a clear baseline to compare with the behavior of the deep Q-learning agent.

While working through the original notebook, I also noticed that the exported version was missing utility functions needed by the training loop. Specifically, the training code called a training-step function which was not defined, preventing the initial deep Q-learning procedure to be completed. I incorporated the missing training aid and time-formatting logic to the updated notebook, but retained the original reinforcement-learning approach. In the code I also implemented a comparison function which can take a trained model's selected path and display its move count next to the A* result. I thought of these improvements as supporting fixes such that the original functionality is still useful together with the new algorithmic advance.

This improvement helps support the course outcome of building and assessing computing solutions utilizing the principles of algorithmic thinking and acceptable computer science methods. It shows that there are multiple approaches to solve the same problem and each has its own trade-offs. A* is deterministic for a given labyrinth and heuristic and will identify an optimal path if the heuristic is appropriate. Deep Q-learning needs to be trained and may act differently based on what the model learnt. By comparing both approaches I was able to think more carefully about when a standard search algorithm may be a better fit than a learning answer and how data structures influence the efficiency and clarity of an implementation.

The most important thing I learned from this upgrade is how much the behavior of an algorithm depends on the data structures supporting it. A * uses a priority queue . This means it always focuses on the most promising state instead of just investigating all alternative in order . Sets are used to avoid processing the same state twice and dictionaries allow to track costs and rebuild the final path. The difficulty was to include the new algorithm without modifying the behavior of the old maze environment. I dealt with that by letting A* read the layout of the maze not modifying the current game state of the pirate. Another difficulty was to make the improved artifact easier to evaluate, hence I added quantifiable results and had the search logic divided into clear functions. Overall, the improvement was a better illustration of my growth in algorithms, data structures and comparing multiple solutions to the same computing challenge.
