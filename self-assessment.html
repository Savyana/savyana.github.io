Professional Self-Assessment

Reflection

How the CS program and these enhancements have influenced my technical approach and career direction.

Introduction

In my Bachelor of Science in Computer Science program I learned that building software is more than just getting code to run. I have gotten more comfortable looking at the structure of a program, determining if an approach is maintainable, and thinking about how someone else would use or support what I have built. My ePortfolio shows development through three projects: software engineering, algorithms and data structures, and databases. Both began as coursework so it gave me the opportunity to revisit my work with a more critical eye.

Professional Background and Collaboration

Having work experience in information technology has helped me to relate classroom concepts to work. I have worked with technology in library environments and in a manufacturing environment where technical problems require both technical knowledge and straightforward communication. When assisting someone in troubleshooting a computer, deployment, or printer issue, I’ve learned to ask questions, explain decisions in plain language, document changes, and think about the people who are impacted by a solution.Those habits count for software development too. These portfolio projects were individual projects but helped me develop communication and problem solving habits that I would use in a development team.

Technical Growth

As part of the coursework, I learned Java, Python, databases, software design, security considerations, etc. I created an Android inventory app for CS-360 to learn about the relationship between interface design, persistent storage, and user actions. That work motivated me to improve my software engineering, and it gave me a reason to dig into the organization of code, to separate business rules and make functionality more testable. The additional search logic, reusable rules and unit tests demonstrate how I went beyond a basic working prototype.

Algorithms and Data Structures

I revisited a Treasure Hunt Game from CS-370 for my algorithms improvement. The original project was to use deep Q-learning to navigate a pirate through a maze. I added an implementation of A* pathfinding to compare a heuristic search method with reinforcement learning. This made the role of data structures much clearer to me. The priority queues, sets and dictionaries weren't just details of the implementation; they dictated the way the search explored the maze and reconstructed the result. I started thinking about efficiency and predictability and the trade-offs in choosing an algorithm.

Databases and Security

I enhanced my database using the Animal Shelter Dashboard from CS-340. The application links python code with MongoDB and displays animal records via filters, a table, charts and a map. I focused on better handling of credentials, better validation of input, more specific database error handling, and reusable query operations. Visually, the changes were not as obvious, but they were important for reliability and maintainability. Removing configuration from source code also helped to emphasize the value of thinking about security early, especially when publishing code online.

Portfolio and Career Goals

Together, these artifacts illustrate various aspects of the development process: developing software that is more maintainable, evaluating algorithmic approaches, and working responsibly with persistent data. They also show how I respond to an existing codebase vs. assuming the first version is done. Hopefully, I can utilize my IT background and computer science degree as I advance in my career to move into more software development and systems work. I am particularly interested in using coding, troubleshooting and automation to solve everyday problems with tools. This portfolio is my starting point for demonstrating to employers not only what I have built but also how I assess, enhance, and communicate my work.
