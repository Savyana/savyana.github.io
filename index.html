Introduction

Throughout my Bachelor of Science in Computer Science program, I have learned that building software is about more than getting code to run. I have become more comfortable examining how a program is structured, deciding whether an approach is maintainable, and thinking about how someone else would use or support what I have built. My ePortfolio shows that growth through three projects focused on software engineering, algorithms and data structures, and databases. Each started as coursework and gave me a chance to revisit my work with a more critical perspective.

Professional Background and Collaboration

My experience in information technology has helped me connect classroom concepts to practical work. I have supported technology in library environments and in a manufacturing setting, where technical problems need clear communication as well as technical knowledge. Helping someone troubleshoot a computer, deployment, or printer issue has taught me to ask questions, explain decisions in plain language, document changes, and consider the people affected by a solution. Those habits matter in software development too. Although these portfolio projects were individual assignments, they strengthened the communication and problem-solving habits I would bring to a development team.

Technical Growth

My coursework has exposed me to Java, Python, databases, software design, and security considerations. In CS-360, I worked with an Android inventory application and learned how interface design connects to persistent storage and user actions. Revisiting that work for my software engineering enhancement gave me a reason to look more closely at organizing code, separating business rules, and making functionality easier to test. The additional search logic, reusable rules, and unit tests show how I moved beyond a basic working prototype.

Algorithms and Data Structures

For my algorithms enhancement, I revisited a Treasure Hunt Game from CS-370. The original project used deep Q-learning to guide a pirate through a maze. I added an A* pathfinding implementation to compare a heuristic search method with reinforcement learning. This made the role of data structures much clearer to me. Priority queues, sets, and dictionaries were not just implementation details; they shaped the way the search explored the maze and reconstructed the result. I learned to think about efficiency, predictability, and the trade-offs involved in selecting an algorithm.

Databases and Security

My database enhancement used the Animal Shelter Dashboard from CS-340. The application connects Python code to MongoDB and displays animal records through filters, a table, charts, and a map. I focused on safer credential handling, stronger input validation, more targeted database error handling, and reusable query operations. Those changes were less obvious visually, but they mattered for reliability and maintainability. Moving configuration out of source code also reinforced the importance of considering security early, especially when publishing code online.

Portfolio and Career Goals

Together, these artifacts demonstrate different parts of the development process: building software that is easier to maintain, comparing algorithmic approaches, and working responsibly with persistent data. They also show how I respond to an existing codebase instead of assuming that the first version is finished. As I continue my career, I want to build on my IT background and computer science degree by taking on more software development and systems-focused work. I am especially interested in applying coding, troubleshooting, and automation to tools that solve everyday problems. This portfolio is a starting point for showing employers not only what I have built but also how I evaluate, improve, and explain my work.
